## Goal
Build a JDS Logistics internal portal (React/Vite/Tailwind) with admin dashboard tabs, job creation, AI document extraction (Gemini primary + Groq fallback), employee dashboard, and container tracking

## Constraints & Preferences
- Visual style: enterprise light theme — navy sidebar (#1a4fa0), page bg #f4f6f9, card bg white with #e2e6ed borders (1.5px), Inter font, JetBrains Mono for mono, 14px base
- Sidebar 230px wide, sectioned nav (OPERATIONS/FINANCE/COMPLIANCE/AI TOOLS) with count badges, fixed position
- All cards rounded-xl shadow-sm, hover:shadow-md hover:border-[#d0d6e0]
- Table headers: bg-[#f8f9fb] text-[#8a96a8] px-4 py-3 uppercase tracking-wide
- Badges: priority/mode/RMS with border + semantic colors (red/amber/green/gray)
- No external icon libraries; use actual UTF-8 characters (not `\u` escapes)
- useAuth() for user context; supabase.js client
- Delete buttons: only admin or original uploader can delete documents
- All Jobs search: numeric prefix match on job number, resets on tab switch
- Container tracking: frontend calls backend, never scrapes directly; carrier mandatory in job form
- No cron jobs, no background scraping, no automatic polling
- Backend: TypeScript/Express, 7 carrier adapters (Maersk, Hapag-Lloyd, CMA-CGM, MSC, ONE, OOCL, COSCO) with hidden API first, Playwright fallback
- AI extraction: Gemini 2.5 Flash primary, Groq Llama 4 Scout fallback; pdfjs-dist for PDF→image (3 pages max, 900px width, 0.6 quality)
- Multimodal requests limited to 5 images per batch; 1–2s delay between Gemini chunk calls, 2–4s for Groq
- activeNav synced with URL via `?tab=` search param
- Container tracking: **1-card-per-job** 3-column grid with expandable container rows, job card click opens slide-in **JobDetailPanel** (520px, right side, animated) with per-container cards (8-field grid, event history, notes, Update/+Add Event buttons)
- Container tracking data: containers from `job.containers` string; `container_tracking` table for optional enrichment only (status, milestones, notes)
- UpdateStatusModal includes Port In, Port Out, CFS Gate In fields
- EmployeeDashboard: same navy sidebar; Documents tab visible to all; Container Tracking read-only; OCR Extract for Akshyani only
- Supabase RLS DELETE policies for jobs, documents, job_extractions applied
- OCRSection lives at `src/components/OCRSection.jsx` (shared between both dashboards); `FIELD_LABELS_OCR` and `OCR_SECTIONS` exported as named exports
- Build uses Vite 8 + Rolldown
- AdminDashboard now split into **8 separate component files** for isolated editing: ControlTower.jsx, JobDetailView.jsx, DocumentsSection.jsx, ContainerTrackingSection.jsx, PaymentsSection.jsx, ComplianceSection.jsx, OCRSection.jsx, and the main AdminDashboard.jsx

## Key Decisions
- **File splitting**: AdminDashboard.jsx was split into 8 separate files so future edits cannot accidentally overwrite unrelated components — each component is isolated, editable independently
- Container tracking data: containers from `job.containers` string (not `container_tracking` table); tracking table used only for optional enrichment
- Container tracking: 1-card-per-job 3-column grid with expandable rows (not per-container cards)
- Employee Dashboard Container Tracking read-only: grid with expandable rows but no Update/+Event buttons
- AI extraction: Gemini 2.5 Flash primary + Groq Llama 4 Scout fallback (Gemini faster/better vision)
- OCRSection moved to shared component file at `src/components/OCRSection.jsx`
- Job deletion is permanent with cascading deletes and `.select()` verification
- UpdateStatusModal includes Port In, Port Out, CFS Gate In fields
- `extractedFields` stores full `job_extractions` row; JSX reads through `extractedFields.extracted_data?.[k]?.value`
- All extracted component files import their own `classNames` helper + required sub-utilities to stay self-contained
